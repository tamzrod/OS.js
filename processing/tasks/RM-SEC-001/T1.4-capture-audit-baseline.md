## Purpose

Produce dated, machine-readable full and production security audit evidence from clean installations tied to the exact commit, lockfile, and supported toolchain.

## Inputs

- Completed evidence contract from T1.2.
- Migrated and verified lockfile from T1.3.

## Dependencies

- Satisfied: T1.3 completed and passed P5 review.

## Scope

### In scope

- Run isolated clean installs with and without lifecycle scripts as defined by P2.
- Capture full and production-only npm audit JSON.
- Record commands, timestamps, exit codes, vulnerability counts, provenance, and hashes.
- Commit a concise human-readable baseline summary.
- Retain large machine outputs under the defined CI policy.

### Out of scope

- Running `npm audit fix`.
- Suppressing or accepting findings.
- Remediating dependencies.
- Treating audit exit code 1 as failure to collect valid evidence.

## Change surface

- CI evidence workflow or scripts defined by T1.2.
- `docs/evidence/security-baseline/` — audit summary and manifest entries.
- No manifest or lockfile changes are allowed.

## Steps

1. Verify clean source, toolchain, and lockfile identity.
2. Run the reduced-exposure clean install and capture its log.
3. Run the isolated lifecycle-enabled clean install and capture its log.
4. Capture full and production-only audit JSON without truncation.
5. Validate JSON, derive counts, hash outputs, and update the evidence manifest.
6. Confirm evidence generation did not modify source or lockfiles.

## Exit condition

Both audit scopes and both install modes have traceable, valid, hashed evidence, and the committed summary agrees with the machine-readable audit metadata.

## Verification

```sh
npm audit --json
npm audit --omit=dev --json
node -e "JSON.parse(require('fs').readFileSync(process.argv[1], 'utf8'))" <audit-json>
git diff --exit-code -- package.json package-lock.json
git diff --check
```

The evidence harness must preserve expected audit non-zero exit codes while still verifying valid JSON output.
