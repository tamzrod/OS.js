# T2.4 — Remove client credential persistence

**Roadmap:** [`RM-SEC-001`](../../roadmap/security-risk-patching.md)  
**Goal:** G2 — Remove vulnerable cookie handling  
**Status:** Complete — awaiting P5 review
**Current position:** P4 G2
**Owner:** Unassigned  
**Created:** 2026-11-11  
**Updated:** 2026-11-11

## Purpose

Remove `js-cookie` and all authentication credential persistence from the forked client while preserving the reviewed authentication contract.

## Inputs

- Reviewed T2.3 red tests.
- P2 compatibility and fail-closed configuration design.

## Dependencies

- Satisfied: T2.3 red tests passed P5 review with six deterministic legacy-behavior failures.

## Scope

### In scope

- Remove the `js-cookie` import, dependency, bundled code, and cookie read/write/removal calls.
- Remove legacy cookie defaults from client configuration.
- Reject an own Boolean `auth.cookie.enabled: true` value with a targeted migration error before credentials are collected.
- Ignore inherited policy properties and reject malformed own policy types.
- Preserve adapter calls, callbacks, events, settings load, logout, and standalone behavior.
- Make all T2.3 security and compatibility tests pass.

### Out of scope

- Session-resume endpoints.
- Generic cookie adapters or attribute allowlists for steady-state use.
- Server session secret, store, fixation, or flag remediation.
- Root lockfile integration.

## Change surface

- `vendor/osjs-client/src/auth.js` — remove persistence and add migration guard.
- `vendor/osjs-client/src/config.js` — remove legacy cookie defaults.
- `vendor/osjs-client/package.json` and client-local lockfile — remove `js-cookie`.
- Client tests and migration documentation.

## Steps

1. Add the configuration migration guard using own-property and explicit-type checks.
2. Remove startup credential replay.
3. Remove login writes and logout/remediation cookie calls.
4. Remove the dependency and rebuild the client package.
5. Run security, compatibility, build, and package-content tests.
6. Verify no alternate browser storage receives login values.

## Exit condition

The forked client contains no `js-cookie` dependency or implementation, persists no submitted authentication values, fails closed on legacy enablement, and passes all reviewed tests.

## Verification

```sh
npm --prefix vendor/osjs-client test -- --runInBand
npm --prefix vendor/osjs-client ls js-cookie --all
rg -n "js-cookie|JavaScript Cookie v|Cookies\\.(get|set|remove)" vendor/osjs-client
git diff --check
```

Revert only T2.4 production changes and client-local dependency metadata; the imported baseline and red tests remain.
