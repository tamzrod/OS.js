## Purpose

Determine whether the official CycloneDX npm generator can represent the frozen invalid-peer baseline without modifying the project dependency graph or hiding the peer-conflict finding.

## Inputs

- T1.5 blocker evidence showing npm 11 `ESBOMPROBLEMS`.
- Frozen lockfile SHA-256 `5ab111720c4d3159aece1462feae3ff45bd470b73af19ea0683f0c4ee828a10d`.
- Official `CycloneDX/cyclonedx-node-npm` documentation for `--package-lock-only`, `--ignore-npm-errors`, reproducible output, and JSON validation.

## Dependencies

- Satisfied: T1.5 reached a reproducible native npm blocker and passed P5 scope review.

## Scope

### In scope

- Select and pin one exact official `@cyclonedx/cyclonedx-npm` release compatible with Node 26/npm 11.
- Resolve and record the package tarball URL and registry integrity before execution.
- Run it ephemerally in an isolated tool directory, never as a project dependency.
- Use lockfile-only and ignore-npm-errors modes while separately preserving the known peer error.
- Validate whether output contains the root application and the expected frozen dependency graph.
- Confirm `package.json` and `package-lock.json` remain byte-identical.

### Out of scope

- Changing, overriding, downgrading, or patching Hyperapp packages.
- Adding a generator to project dependencies or the project lockfile.
- Treating `--ignore-npm-errors` as permission to ignore unknown errors.
- Producing final T1.5 SBOM evidence before the runner is approved.

## Exit condition

Either a pinned external runner is approved with integrity, isolation, structural-validation, and known-error controls documented, or the experiment proves it unsuitable and T1.5 remains blocked with no project graph change.

## Verification

```sh
sha256sum package.json package-lock.json
npm view @cyclonedx/cyclonedx-npm@<exact> dist.tarball dist.integrity --json
git diff --exit-code -- package.json package-lock.json
git diff --check
```
