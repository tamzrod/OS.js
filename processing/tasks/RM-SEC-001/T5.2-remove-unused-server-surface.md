# T5.2 — Remove unused production server surfaces and dependency roots

**Goal:** G5 — Reduce and patch the server surface  
**State:** P4 partial implementation; T5.2 remains open  
**Depends on:** T5.1 accepted (production startup remains blocked)  
**Scope:** Disabled provider registration, route elimination, unused runtime packages, exact graph evidence

## Boundary

T5.1 denies *every* Node production boot because the current default null auth adapter and server internals are not yet fit for production. T5.2 must **not** relax that gate. Product server requirements remain unconfirmed; do not invent or silently enable them.

## Ordered work

1. Capture exact routes, service consumers and provider lifecycle for Core, Package, VFS, Auth and Settings; classify each as development-only, statically buildable, or explicitly required by a documented Media Intelligence consumer.
2. Remove unnecessary production provider registrations without relying on UI-only hiding. Confirm no startup side effects (including WebSocket and session) happen for disabled features.
3. Separate build-time CLI and package discovery from runtime package roots. Avoid deleting useful local-development functionality unless removing it is unavoidable and tested.
4. Remove the direct music player/metadata parser root only after verifying no product consumer needs it. Regenerate the npm lock with the pinned Node 26.13.0/npm 11.20.0 toolchain and retain the before/after dependency inventory.
5. Verify absent routes and non-created listeners in isolated tests. Ensure residual capabilities are denied by default, and arbitrary username login remains impossible.
6. Run `npm ci`, root tests, G1–G4 security suites, browser build, full and production audits and SBOM comparison. Record actual findings and any compatibility breaks.

## Acceptance

- Every removed feature has a documented consumer decision and a negative route/startup test.
- Unused production dependency roots are absent from the exact lock graph.
- No new insecure fallback, credential, or deployable server path.
- Retained browser/client behaviors remain covered; CI evidence is linked to the tested head.
- G5 stays open: retained HTTP/WS chains and resource-limit hardening are T5.3–T5.6.
- No master modification, PR merge, release or deployment.

## P4 checkpoint — public registration route removal (2026-11-18)

- `vendor/osjs-server/src/providers/auth.js`: POST `/register` is no longer registered by default. For isolated local development, registration requires both `development === true` and an **own** boolean `auth.allowRegistration === true` property. Even an explicit opt-in cannot expose registration when `development !== true`.
- `vendor/osjs-server/src/config.js`: default `auth.allowRegistration: false`.
- `scripts/security/g5-registration-routes.test.cjs`: exercises actual provider route registration with isolated service mocks. Checks default-off, production-off, non-boolean values and inherited opt-in, plus the explicit development-only case.
- `.github/workflows/g5-capability-contract.yml`: runs the registration regression alongside the existing pre-construction production startup guard tests.
- T5.1's production server denial remains unchanged. This patch does **not** mean the unsafe default login adapter is fixed or that the server is production-ready.
- No dependency or lockfile changes were made yet. The remaining T5.2 work—provider lifecycle/consumer decisions, music player/CLI dependency removal, clean audits/SBOMs and compatibility verification—remains open.

## P4 checkpoint — null-auth fallback removal (2026-11-18)

A second access-control weakness was confirmed in `vendor/osjs-server/src/auth.js`: constructing a custom authentication adapter previously initialized the accept-any-username null adapter first, then swallowed a custom adapter initialization exception. The fallback could silently preserve permissive authentication.

- Production context now rejects an implicit or explicit null adapter before initialization.
- Production requires an adapter factory returning an object with a callable `login`; a missing/invalid adapter or thrown factory error now fails closed instead of restoring null auth.
- Isolated development continues to support the historical default adapter for backward compatibility.
- `scripts/security/g5-auth-adapter.test.cjs` covers default/explicit null auth, production-environment override, invalid adapters, thrown constructor, and preservation of development-only behavior.
- `.github/workflows/g5-capability-contract.yml` now runs the expanded auth, registration and startup suite.
- **Boundary:** a custom adapter is not automatically verified as secure. The T5.1 production startup gate remains closed, including when a custom adapter is present.
- No dependency lock or provider graph changes in this checkpoint. T5.2 remains **OPEN** pending provider/consumer removal, retained dependency graph evidence, full tests/audit and SBOMs.
