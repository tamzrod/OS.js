# T1.1 — Enforce the supported toolchain

**Roadmap:** [`RM-SEC-001`](../../roadmap/security-risk-patching.md)  
**Goal:** G1 — Freeze and reproduce the baseline  
**Status:** Complete  
**Current position:** P5 G1 — Review and Continue  
**Owner:** Unassigned

**Updated:** 2026-11-09

## Purpose

Make Node.js 26.13.0 and npm 11.20.0 the single machine-readable and documented toolchain contract for local development, CI, and the development container.

## Inputs

- [`P1 G1 analysis`](../../../docs/p1-g1-baseline-reproducibility-analysis.md).
- [`P2 G1 plan`](../../../docs/p2-g1-baseline-reproducibility-plan.md), decisions D1 and D2.
- Official Node.js 26.13.0 LTS and npm 11.20.0 release metadata linked by the P2 plan.

## Dependencies

- None. This is the first G1 action task.

## Scope

### In scope

- Add `.nvmrc` containing the exact Node version.
- Set bounded Node and exact npm declarations in `package.json`.
- Add `packageManager` and failing `devEngines` guards.
- Update both GitHub Actions workflows to use exact Node 26.13.0 and `npm ci`.
- Replace the Node 10 development-container base with the exact selected version and pin global tools or remove them.
- Correct runtime instructions in `README.md`.
- Add a pre-install/CI assertion if the manifest guards do not produce a clear failure.

### Out of scope

- Regenerating `package-lock.json`.
- Upgrading Webpack or application dependencies.
- Making the application build pass.
- Adding the legacy OpenSSL provider.
- Capturing audits or SBOMs.

## Change surface

- `.nvmrc` — exact Node runtime.
- `package.json` — `engines`, `packageManager`, and `devEngines`.
- `.github/workflows/node.yml` — exact runtime and version assertion.
- `.github/workflows/test.yml` — exact runtime and deterministic install command.
- `Dockerfile` — exact supported Node development image and deterministic tooling.
- `README.md` — supported local runtime instructions.
- A small version-check script only if declarative enforcement is insufficient.

## Steps

1. Add the exact runtime and package-manager declarations.
2. Update CI to install and assert the declared versions before dependency installation.
3. Update the development container without introducing unpinned global packages.
4. Replace obsolete README runtime guidance.
5. Test accepted and rejected version paths without changing the lockfile.
6. Review the diff for accidental dependency or build changes.

## Exit condition

Every supported entry point identifies Node 26.13.0/npm 11.20.0 consistently, the correct versions pass the guard, unsupported versions fail with a clear message, and `package-lock.json` is unchanged.

## Verification

```sh
node --version
npm --version
npm pkg get engines packageManager devEngines
git diff --exit-code -- package-lock.json
git diff --check
```

CI configuration and the development-container base must also be inspected for the exact versions. The task environment must use Node 26.13.0/npm 11.20.0 before claiming the positive version check passed.

## Evidence

- Added `.nvmrc` with Node `26.13.0`.
- `package.json` now declares `packageManager: npm@11.20.0`, bounded Node/npm engines, and failing `devEngines` guards.
- Both GitHub Actions workflows use `.nvmrc`, `npm ci`, and an exact Node/npm assertion.
- The development container uses `node:26.13.0` and pins `nodemon@3.1.10`; its entrypoint uses `npm ci`.
- README runtime guidance now names the exact toolchain and prohibits `--openssl-legacy-provider`.
- Negative test: Node `v24.16.0` / npm `11.13.0` was rejected with `EBADDEVENGINES`.
- Positive test: the official Node `v26.13.0` binary reported npm `11.20.0` and `npm pkg get engines packageManager devEngines` completed successfully.
- Downloaded Node archive SHA-256 was `d28a96af6c38596f6d9d97c0ee531c13d238d757742387d1928de822d959e997`, matching the official Node 26.13.0 Linux x64 release checksum recorded in the P2 source.
- A clean temporary `npm ci --ignore-scripts` installed 1,387 packages under the accepted toolchain.
- `package-lock.json` remained byte-identical with SHA-256 `d086b6df8d81fba827c138aac6a194a923b58bf2eb1d47760766e01aa580d726`.
- `package.json` and both workflow YAML files parsed successfully; `git diff --check` passed.
- The full container image download was stopped after stalling; positive runtime verification used the smaller official signed-release binary instead. The Dockerfile configuration was inspected but the image build was not part of this task's exit condition.

- **New findings:** npm 11.20.0 still emits the expected old-lockfile warning and fetches supplemental metadata; T1.3 remains responsible for controlled lockfile migration. The clean install continues to report the legacy vulnerability baseline.
