## Workflow

`.github/workflows/g1-security-evidence.yml` provides a manually triggered, read-only GitHub Actions job for the complete G1 evidence set. It uses:

- Exact Node.js version from `.nvmrc` and an explicit Node 26.13.0/npm 11.20.0 assertion.
- Immutable, review-verified action SHAs for `checkout` v7.0.1, `setup-node` v7.1.0, and `upload-artifact` v7.0.2.
- Minimal `contents: read` permissions, no persisted checkout credentials, one-hour timeout, and non-cancelling concurrency.
- A clean-checkout assertion before any evidence command.
- Scripts-disabled project installation before classification and build capture.
- An isolated, exact SBOM tool environment containing `@cyclonedx/cyclonedx-npm@7.0.0`, patched AJV 8.20.0, and zero accepted audit findings.
- Ninety-day artifact retention, the maximum configured by this workflow.

## Fail-closed orchestration

`scripts/security/run-g1-evidence-ci.js` coordinates three evidence groups:

1. Clean installs and full/production audits.
2. Full/production CycloneDX SBOMs with exact diagnostic filtering, reproduction, schema validation, and recursive-reference validation.
3. Complete dependency classification, package discovery, and the expected Webpack build failure.

Each group writes a separate manifest under one uploaded artifact tree. Every manifest must pass `validate-evidence-manifest.js`. The orchestrator fails if the checkout is dirty before or after generation.

`capture-classification-build-baseline.js` runs discovery and build in a disposable copy linked to the clean installed graph, preventing generated `dist` and `packages.json` content from dirtying the checkout. It requires:

- 1,392 classified packages.
- Zero unknown packages and unresolved edges.
- Eleven discovered OS.js packages.
- Build exit code 1 containing `ERR_OSSL_EVP_UNSUPPORTED`.
- No `--openssl-legacy-provider` text.

The audit and SBOM capture helpers now accept a `clean` source-state token, producing manifests with `source.dirty: false` and `statusSha256: null`. Their existing dirty-development mode remains available with a status hash.
