# T1.5 SBOM Generation Blocker

**Roadmap:** `RM-SEC-001`  
**Goal:** G1 — Freeze and reproduce the baseline  
**Toolchain:** Node.js 26.13.0 / npm 11.20.0  
**Lockfile SHA-256:** `5ab111720c4d3159aece1462feae3ff45bd470b73af19ea0683f0c4ee828a10d`  
**Status:** Blocked pending P5 review

## Result

npm cannot generate a CycloneDX SBOM for the frozen baseline because the dependency tree contains an invalid peer relationship:

```text
npm error code ESBOMPROBLEMS
npm error invalid: hyperapp@1.2.10, 1.1.x required by hyperapp-nestable@1.1.0
```

The lockfile confirms:

- `hyperapp@1.2.10` is installed at `node_modules/hyperapp`.
- `hyperapp-nestable@1.1.0` declares peer dependency `hyperapp: 1.1.x`.

## Attempts

The following read-only commands all produced the same `ESBOMPROBLEMS` result and no SBOM document:

```sh
npm sbom --sbom-format=cyclonedx --sbom-type=application
npm sbom --package-lock-only --sbom-format=cyclonedx --sbom-type=application
npm sbom --force --package-lock-only --sbom-format=cyclonedx --sbom-type=application
```

Running against the clean installed tree and against the source directory without `node_modules` did not change the result. The production-only command was not treated as valid evidence because the full baseline command could not complete.

## Scope decision

No dependency was changed and no custom SBOM was synthesized. Fixing the peer relationship would alter the frozen dependency graph; adding or writing another generator would violate T1.5's planned constraint against introducing a generator. P5 must decide whether to insert a bounded prerequisite task or revise the approved SBOM approach.

`package.json` and `package-lock.json` retain their pre-attempt hashes. MI-P6 remains blocked.
