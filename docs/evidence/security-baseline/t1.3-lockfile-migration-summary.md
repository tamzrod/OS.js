## Reviewed additions

npm 11 added three optional development entries required to describe the existing optional `fsevents` chain completely:

- `bindings@1.5.0`
- `file-uri-to-path@1.0.0`
- `nan@2.30.0`

These entries are not production dependencies. Their exact paths, versions, registry URLs, integrity values, and classifications are pinned in `t1.3-approved-additions.json`. The comparison fails if an addition differs from that allowlist, if an approved addition is missing, or if any existing entry is removed or changed.

## Migration behavior

The first format conversion produced lockfile SHA-256 `6af10...` but was rejected because `npm ci` reported that the lockfile omitted the three packages above. A second metadata-only `npm install --package-lock-only --ignore-scripts` reconciled the optional dependency metadata. This intermediate failure was not installed in the repository.

Two clean `npm ci --ignore-scripts` runs then succeeded against the reconciled lockfile. Both runs left its SHA-256 byte-identical at `5ab111720c4d3159aece1462feae3ff45bd470b73af19ea0683f0c4ee828a10d`. The legacy audit findings and deprecation warnings remain baseline observations for later remediation tasks; T1.3 did not attempt dependency upgrades.

## Reproduction

Create inventories before and after migration, then compare them with the reviewed allowlist:

```sh
node scripts/security/lockfile-inventory.js inventory package-lock.json inventory.json
node scripts/security/lockfile-inventory.js compare \
  before-inventory.json after-inventory.json comparison.json \
  docs/evidence/security-baseline/t1.3-approved-additions.json
```

Full normalized inventories and clean-install logs belong in retained CI artifacts under the evidence contract. The small comparison, allowlist, deterministic helper, and this review summary are committed for source review.
