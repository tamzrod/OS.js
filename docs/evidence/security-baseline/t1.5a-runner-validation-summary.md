## Required controls for T1.5

The runner's `--validate` path stops when its internal npm query reports the known invalid peer. With `--no-validate`, it emits a complete structurally consistent document while preserving the npm error on standard error. Therefore approval is conditional on all of these controls:

1. Execute only pinned runner version `7.0.0` with the recorded registry integrity.
2. Bind both Node and npm explicitly to the approved toolchain.
3. Use `--package-lock-only`, `--ignore-npm-errors`, and reproducible output.
4. Capture standard error and accept only `ELSPROBLEMS` for `hyperapp@1.2.10` caused by `hyperapp-nestable@1.1.0`; reject every unknown error.
5. Independently validate CycloneDX identity, recursive components, dependency references, scope reduction, and JSON/schema structure.
6. Confirm project manifest and lockfile hashes remain unchanged.

The first trial used the system Node 24/npm by discovery and correctly failed the project's `devEngines` guard. This proves T1.5 must not rely on ambient executable discovery.
