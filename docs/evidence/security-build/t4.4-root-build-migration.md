# T4.4 root browser build migration

## Implementation

The root browser build now uses the exact root-managed Webpack 5.112.2 toolchain through `scripts/build-webpack.cjs`. The migration replaces `file-loader` with Webpack 5 asset modules, replaces `optimize-css-assets-webpack-plugin` with `css-minimizer-webpack-plugin`, quotes the `OSJS_VERSION` definition, and explicitly preserves the historical `vendors~osjs` JavaScript and CSS chunk names.

The build completed under Node 26.13.0 without a legacy OpenSSL provider override. Source-map ingestion excludes already-built fork bundles because their nested upstream TypeScript URLs are not resolvable inputs to the root build; the fork bundles retain their own validated maps.

## Explicit differences from the comparison build

- Webpack 5 content hashes shorten the two image filenames while preserving their bytes.
- JavaScript, CSS, maps, and minified HTML have new hashes because they are emitted by the modern toolchain.
- Webpack 5 emits `osjs.js.LICENSE.txt`, increasing the inventory from 37 to 38 files while preserving license notices.
- The HTML minifier emits safe unquoted local asset attributes; the contract extractor now recognizes quoted and unquoted references.

`scripts/security/verify-g4-root-build.cjs` accepts only these normalized differences and rejects drift in inventory classes, HTML references, font identities, image identities, required assets, or obsolete Webpack 4 configuration tokens.

The first P5 replay exposed that the initial contract had consumed an ignored local `vendor/osjs-dialogs/dist/main.css.map`. That replay was rejected. The map and the common/dialogs license sidecars are now explicit retained inputs, and the corrected contract above was reproduced twice from the fresh clone.
