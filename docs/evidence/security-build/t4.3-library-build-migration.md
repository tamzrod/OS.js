# T4.3 fork-owned library build migration

## Implementation

Common, client, dialogs, and settings now invoke the root-pinned Webpack binary explicitly. Their Webpack 5 configurations preserve the existing output contracts while replacing Webpack-4-only APIs:

- common emits a CommonJS library;
- client emits the named `osjsClient` UMD library, extracted CSS, source maps, and asset/resource images;
- dialogs emits the named `osjsDialogs` UMD library, extracted CSS, and source maps;
- settings preserves its `osjs: OSjs` external and emits JavaScript/source maps;
- css-minimizer-webpack-plugin replaces optimize-css-assets-webpack-plugin;
- Webpack 5 asset modules replace file-loader.

The builds ran in dependency order from a clean clone under Node 26.13.0 with Webpack 5.112.2 and no OpenSSL override. Common was rebuilt first and its output fed into the client, dialogs, and settings builds.

## Contract and compatibility checks

`scripts/security/verify-g4-library-builds.cjs` passed, checking CommonJS exports, both UMD global/AMD names, the settings `OSjs` external, CSS extraction, all relative CSS assets, valid source maps, and absence of `deepmerge` from retained bundles.

The G3 integration verifier and hostile-object green suite pass against the new bundles. An isolated exact Jest 30.5.2 runner (outside the release lock) passed all 12 common safe-object tests and all 321 client tests.

The client build reports Sass deprecations for historical `@import` and slash-division syntax. Settings reports one existing named-import compatibility warning. Neither warning represents missing output or a changed public contract; both remain recorded for cleanup before G4 closure.
