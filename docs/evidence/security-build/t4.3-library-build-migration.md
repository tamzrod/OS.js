# T4.3 fork-owned library build migration

## Implementation

Common, client, dialogs, and settings now invoke the root-pinned Webpack binary through `scripts/build-webpack.cjs`. The wrapper fixes both `NODE_ENV` and Webpack mode, preventing a package invocation from silently producing development output. Their Webpack 5 configurations preserve the existing output contracts while replacing Webpack-4-only APIs:

- common emits a CommonJS library;
- client emits the named `osjsClient` UMD library, extracted CSS, source maps, and asset/resource images;
- dialogs emits the named `osjsDialogs` UMD library, extracted CSS, and source maps;
- settings preserves its `osjs: OSjs` external and emits JavaScript/source maps;
- css-minimizer-webpack-plugin replaces optimize-css-assets-webpack-plugin;
- Webpack 5 asset modules replace file-loader.

The builds ran in dependency order from a clean clone under Node 26.13.0 with Webpack 5.112.2 and no OpenSSL override. Common was rebuilt first and its output fed into the client, dialogs, and settings builds.

## Contract and compatibility checks

`scripts/security/verify-g4-library-builds.cjs` passed, checking CommonJS exports, both UMD global/AMD names, the settings `OSjs` external, CSS extraction, all relative CSS assets, valid source maps, and absence of `deepmerge` from retained bundles.

The G3 integration verifier and hostile-object green suite pass against the new bundles. An isolated exact Jest 30.5.2 runner (outside the release lock) passed all 12 common safe-object tests and all 321 client tests.

Two consecutive dependency-ordered builds in the clean clone produced the exact hashes above. The client build reports Sass deprecations for historical `@import` and slash-division syntax plus Webpack's advisory entrypoint-size warning. Settings reports one existing named-import compatibility warning. Neither warning represents missing output or a changed public contract; all remain recorded for cleanup before G4 closure.

The generated common/dialogs license sidecars and dialogs CSS source map are retained even though the upstream package `.gitignore` historically ignored them. This prevents downstream root builds and source-map verification from depending on stale local outputs.

The first P5 replay also caught that the original package scripts defaulted to development mode when called without an ambient `NODE_ENV`. That replay was rejected. The shared wrapper and explicit production/development script arguments are the corrective control; the retained artifacts above are the corrected package-script outputs.

## P5 acceptance

Fresh remote commit `16b3a990cd34ac9ba990bbd3a590090f5bd4eac9` was installed with Node 26.13.0/npm 11.20.0, then rebuilt common, client, dialogs, and settings in dependency order using only the root-managed toolchain. The rebuild left the checkout clean and reproduced all six principal hashes above. `verify-g4-library-builds.cjs`, the G3 integration verifier, and the hostile-object green suite passed. No OpenSSL legacy-provider flag or package-local Webpack installation was used. T4.3 is accepted.
