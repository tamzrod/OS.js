# T4.5 browser behavior and build-policy verification

## Static-host smoke test

The production artifact from fresh remote commit `997182c7` was served from a bounded localhost static server and loaded in the in-app Chromium browser. The document reached `readyState=complete`, rendered the OS.js root and login form, and loaded both expected scripts and both expected stylesheets:

- `vendors~osjs.js` and `osjs.js`;
- `vendors~osjs.css` and `osjs.css`.

The server observed successful `200` requests for the favicon, wallpaper, Roboto 400/700 WOFF2 fonts, both JavaScript chunks, and both CSS chunks. The only console warning was the expected failed `/login` request because a static server deliberately has no authentication API; it was not a missing build artifact or browser-policy violation.

## CSP and artifact policy

The same artifact was served with:

```text
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self' ws: wss:; object-src 'none'; base-uri 'none'
```

It again reached a complete OS.js login UI with no CSP console violation. Direct header checks returned `200` with `nosniff` and correct MIME types for JavaScript/CSS source maps, WOFF2 fonts, and PNG images.

Source maps are an explicit public-artifact policy for this roadmap stage: all four maps are emitted, referenced by their corresponding JS/CSS files, valid JSON, and available as `application/json`. T4.7 closure evidence must continue to retain them unless a later release decision deliberately changes this policy.
