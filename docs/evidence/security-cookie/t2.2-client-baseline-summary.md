## Published-package comparison

- Package identity and entry points match: name `@osjs/client`, version `3.7.1`, JavaScript `dist/main.js`, CSS `dist/main.css`, and declarations `index.d.ts`.
- The public source entry exposes 28 named exports. The retained verifier freezes that inventory.
- `index.d.ts` is byte-identical to npm 3.7.1 (SHA-256 `ac35fb21572ebf04baeb49933145d4ea1ab24df2f24a795fb83967d168283ee0`).
- Both PNG assets are byte-identical to npm 3.7.1.
- The generated package contains the same 11 paths as npm 3.7.1.
- `main.css.map` is byte-identical. Generated `main.js`, `main.js.map`, and `main.css` are not byte-identical.

The generated-output drift is dependency/toolchain-derived: the source tree is the exact tagged source, but upstream published without a lockfile and current semver resolution selects a newer compatible tool graph. No source-derived or unexplained package-surface difference was found. Byte equality of generated bundles is therefore not used as a false acceptance criterion; source provenance, public exports, declarations, assets, package paths, and successful clean builds are the retained baseline.

## Security observation

The isolated development graph reports 93 audit findings (12 low, 62 moderate, 18 high, 1 critical). This is evidence only and does not alter the already established production-risk gate. It reinforces that this graph is a reproduction baseline, not an approved dependency destination.

## Reproduction commands

Run in a disposable copy of `vendor/osjs-client`:

```sh
npx --yes --package=node@26.13.0 --package=npm@11.20.0 -c 'npm install --include=dev --ignore-scripts'
npx --yes --package=node@26.13.0 --package=npm@11.20.0 -c 'npm run eslint && npm run stylelint && npm run jest -- --runInBand'
npx --yes --package=node@26.13.0 --package=npm@11.20.0 -c 'npm run build'
npx --yes --package=node@26.13.0 --package=npm@11.20.0 -c 'NODE_ENV=production npm run build'
```

Repository-level retained verification:

```sh
node scripts/security/verify-client-import.js
```
