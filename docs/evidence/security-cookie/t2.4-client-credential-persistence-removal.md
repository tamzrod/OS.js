# T2.4 client credential-persistence removal evidence

## Result

The forked client contains no `js-cookie` dependency or authentication cookie operation. All 35 suites/317 tests pass, including the reviewed T2.3 security contract and three malformed-policy cases added during remediation, and a production package rebuild succeeds on the frozen toolchain without compatibility flags.

## Implementation

- Removed the `js-cookie` import and all authentication cookie get/set/remove calls.
- Removed the legacy `auth.cookie` defaults.
- Added an own-property-descriptor guard before adapter initialization.
- Own Boolean `enabled: true`, malformed policy objects, accessors, and non-Boolean own values fail closed with migration errors.
- Inherited `enabled` is ignored; own Boolean `false` is tolerated without enabling a persistence surface.
- Login, failed-login events, logout, callback/core events, startup, and standalone behavior remain covered.
