# T3.9 retained safe-object evidence

## P4 implementation

The G3 clean-evidence workflow reproduces the exact committed root lock under the pinned Node/npm toolchain. It installs package-local development graphs only to run compatibility tests; those graphs are not treated as the shipped release graph.

The retained set includes source identity, root full and production audits, full and production CycloneDX SBOMs, root/package integration verification, hostile-object regression tests, client and server compatibility suites, lint checks, and scans of the root lock, reviewed production sources, and retained browser bundles.

G3 acceptance is deliberately narrow: no `deepmerge` package or advisory may occur in the root release lock, release SBOMs, reviewed production sources, or retained browser artifacts, and every classified hostile-object boundary must fail safely. Other audit findings remain release blockers assigned to later roadmap goals.
