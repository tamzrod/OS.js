# T3.5 client safe-object migration evidence

**Result:** all five client merge sites and the adjacent storage/path boundaries use the reviewed safe-object contract
**Compatibility:** 36 suites and 321 tests pass (317 prior tests plus 4 focused security tests)

## Changed boundaries

- Settings and desktop persisted data use explicit array replacement.
- Mountpoint and window options use descriptor-safe merging with explicit function compatibility where required.
- Locale overrides normalize the module namespace and allow documented function leaves.
- Settings namespace and dotted paths pass through `safeSetPath`; reserved segments throw `UnsafeObjectInputError`.
- Local-storage accumulation uses `safeMerge` and rejects reserved storage keys without invoking ordinary-object setters.
- The client directly links the fork-owned common package and no longer declares or imports `deepmerge`.
